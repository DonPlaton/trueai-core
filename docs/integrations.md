# Building on TrueAI: desktop, CI, and editor

Three surfaces need the same five views — what a finding claims, what cleanup
would do, what integrity evidence exists, what provenance was established, and
whether an audit certificate holds. Left to derive those separately from the
schema, they drift: one shows "AI-generated", another shows "attribution string
found", and they are describing the same finding.

`trueai.adapters.views` derives them once. `trueai.adapters.ci`,
`trueai.adapters.ide`, and `trueai.adapters.desktop` format them. None adds a
field the report does not already imply, because a second source of truth is a
second thing to be wrong.

## The sentence that must not be dropped

`FindingExplanation.does_not_claim` says what a finding does **not** establish.
It is derivable from the confidence class and the provenance class, and it is the
first thing an interface drops when it runs short of space. Deriving it centrally
means an interface has to *actively discard* it rather than simply never having
had it — and every adapter here carries it into its output, including the two
formats that only have one line.

| Confidence | Claims | Does not claim |
|---|---|---|
| `deterministic` | The stated trace was observed exactly in these bytes. | That the artifact was generated by AI. |
| `verified` | A mechanism was run and returned this result. | Anything beyond that mechanism's scope. |
| `probabilistic` | A calibrated estimate placed it in this range. | It is a measurement, not provenance, and identifies no author. |
| `heuristic` | A rule of thumb matched. | It is a prompt for review, never evidence of authorship. |

Provenance class adds a second sentence — an attribution string is text anyone
can write, metadata is editable by anyone who can open the file, an observed
provider marker is not a verified one.

## CI

```
trueai scan ./repository -f ci
```

Workflow annotations first, so a runner picks them up as it streams, then a
Markdown job summary a person reads afterwards.

**Both formats are injection boundaries.** A workflow annotation is a single line
of a control stream: a message containing a newline does not produce a malformed
annotation, it produces *a second command*, and finding descriptions come from
the artifact under examination. Every value is escaped for `%`, `CR`, and `LF`,
and every property value additionally for `:` and `,`. A Markdown table cell is
structure, and a pipe in a value rewrites the table around it, so cells are
escaped too.

`CRITICAL` and `HIGH` become error annotations; nothing else does. A job that
failed on every `INFO` finding would be switched off within a week, and a tool
nobody runs finds nothing.

## Editor

```
trueai scan ./repository -f ide
```

LSP-shaped diagnostics keyed by file, as plain dictionaries — no LSP dependency,
because a scanner should not pull one into a CI image that will never open an
editor. `publish_payloads()` returns `textDocument/publishDiagnostics` bodies;
the transport is the extension's.

**A missing range is admitted, not invented.** Most detectors report a byte
offset, and turning one into a line and character needs the file, its encoding,
and its line endings. Getting any of those wrong puts a squiggle under the wrong
text, which is worse than no squiggle because it looks authoritative. A finding
without line information gets a zero-length range at the start of the file and
says so in the message.

**Every scanned file appears, including clean ones**, so an editor can clear
stale markers rather than leaving yesterday's squiggles under text that no longer
has a problem.

Severity is mapped, not equated: TrueAI has five levels and LSP has four.
`CRITICAL` and `HIGH` become `Error`; `INFO` becomes `Hint` and never an error.

## Desktop

```
trueai scan ./repository -f desktop
```

One versioned JSON bundle with all five views assembled. A client checks
`bundle_version` and refuses one it cannot read rather than rendering half of it.

Two details a client should not undo:

- **Coverage sits beside the findings, not under them.** A client that renders
  findings alone shows a clean page for a scan that could not read half the
  repository.
- **`remediation` and `certificate` are `null` when absent**, so "no plan was
  made" is distinguishable from "a plan with nothing in it".

## Integrity, stated carefully

`IntegrityEvidence.visible_content_unchanged` is `True`, `False`, or **`None`**.
`None` when the logical digests are missing, because a check that did not run is
not a check that failed, and an interface that collapsed the two would report an
unverifiable artifact as a damaged one.

## Certificates

`certificate_view()` returns every check separately — identity, signature
presence, signature validity, artifact binding, validity period, revocation —
because one green tick over all six lets four unknowns hide behind one answer.

`CertificateView.attests_only` restates what a TrueAI certificate never asserts,
and it travels with every view: a named scanner version and detector scope found
no scoped indicators in exact artifact bytes at a recorded time. Not human
authorship, and not that AI was never used.

## Stability

`trueai.adapters` is in `PUBLIC_MODULES`, so it is covered by
[API compatibility](api-compatibility.md). The desktop bundle carries its own
`BUNDLE_VERSION` on top, because its shape is a wire format rather than a set of
Python names.
